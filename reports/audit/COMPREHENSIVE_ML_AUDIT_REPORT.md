## 1. Project & Model Architecture Inspected

The audited codebase implements a dual-stage network intrusion detection system (NIDS) trained on the CIC-IDS2017 benchmark. The inference pipeline processes bidirectional flow statistics generated by CICFlowMeter.

### Architecture Specifications:
- **Model Type:** Scikit-Learn `RandomForestClassifier` (Ensemble of 60 decision trees, `max_depth=16`, `criterion="gini"`, `min_samples_split=2`, `min_samples_leaf=1`, `random_state=42`).
- **Feature Space:** 77 numerical network flow features (inter-arrival times, packet length distributions, flow duration, sub-flow characteristics, TCP flag counters, buffer metrics).
- **Preprocessing:** `RobustScaler` (median-centered, interquartile range scaling to withstand heavy-tailed network throughput outliers).
- **Partitioning Strategy:** 80/20 stratified train/test split on 99,964 clean records (`79,971` train flows, `19,993` test flows).
- **Classification Objectives:**
  - **Binary Mode:** Discrimination between `BENIGN` network traffic and malicious `ATTACK` flows.
  - **Multiclass Mode:** 15-class identification covering `BENIGN` and 14 distinct attack types (DDoS, DoS Hulk, PortScan, DoS GoldenEye, FTP-Patator, SSH-Patator, DoS Slowhttptest, DoS slowloris, Bot, Web Attack - Brute Force, Infiltration, Web Attack - Sql Injection, Web Attack - XSS, Heartbleed).

## 6. Data Leakage Audit Findings (TEST 3: WARNING)

A comprehensive 7-point audit was conducted on data preprocessing and flow distributions:

### Check 1: Exact Flow Duplicates (Status: WARNING)
- **Total Flows in Full Dataset:** 99,964
- **Exact Duplicate Flow Vectors:** 3,570 (3.57%)
- **Test Flows Identical to Training Flows:** **879 flows (4.40%)**
- **Overlap Composition:** BENIGN (457), DoS Hulk (350), PortScan (53), SSH-Patator (13), FTP-Patator (6).
- *Root Cause:* Automated attack tools (e.g. DoS Hulk, hping) transmit repetitive HTTP GET floods with identical packet lengths, window sizes, and TCP flags. A random split allows identical feature vectors from the same attack session into both training and testing sets, artificially guaranteeing correct predictions for 4.4% of the test set.

### Check 2: Near-Duplicate Records (Status: WARNING)
- Evaluated normalized Euclidean distance on a 500-sample test slice against the training set.
- **26 samples** had an exact distance of 0.0, and **59 samples** had near-zero distance ($d < 0.01$). This confirms that high density clusters generated by automated scripts leak between partitions.

### Check 3: Target and Label Leakage (Status: PASSED)
- Audited all 77 feature names. Forbidden tokens (`Label`, `Binary_Label`, `Threat_Category`, `Attack_Type`, `Timestamp`, `Flow ID`, `Source IP`, `Destination IP`, `Simulated_Time`) were strictly absent.
- Maximum Pearson correlation with the target variable was $|r| = 0.5139$ (`Bwd Packet Length Std`). Zero direct label proxies exist.

### Check 4: Preprocessing Boundary (Status: PASSED)
- Audited `RobustScaler` fitting in `src/model_trainer.py`.
- `scaler.fit_transform()` was executed solely on `X_train`. The test partition was transformed using `scaler.transform()` without updating center or IQR scale vectors.

### Check 5 & 6: Train/Test Split & Stratification (Status: PASSED)
- The stratified 80/20 split preserved exact class ratios across train and test partitions (maximum proportion delta $< 3.75 \times 10^{-5}$). All 15 classes are represented in both splits.

### Check 7: Capture Session & Port Reliance (Status: WARNING)
- In both classifiers, **`Destination Port` is the #1 most important feature** (Gini Importance: **7.66%** in Binary, **7.37%** in Multiclass).
- **Ablation Test:** Zeroing out `Destination Port` at test time dropped binary accuracy by **2.49%** (to 97.24%).
- *Mechanism:* In the CIC-IDS2017 testbed, attacks were directed at specific target ports (e.g. DoS Hulk against Port 80, FTP-Patator against Port 21, SSH-Patator against Port 22). The trees learned to heavily branch on port numbers, creating a dependency on static environment configuration.

## 10. Problems Discovered

1. **Severe Minority Class Masking:** Weighted F1 (99.51%) creates a deceptive illusion of near-perfection. In reality, Web Attacks (XSS, SQLi, Brute Force) suffer error rates between 40% and 75%, and Botnet precision collapses to 25.53%.
2. **Duplicate Flow Leakage (4.40%):** Monolithic random sampling across PCAP captures allows automated, periodic attack packets with identical flow characteristics to populate both train and test splits.
3. **Destination Port Shortcut Reliance:** `Destination Port` is the single most dominant feature (~7.6% Gini importance). Zeroing out this single feature drops accuracy by 2.49%, indicating that models rely on static port bindings.
4. **Zero-Shot Cross-Day Failure:** Supervised Random Forests fail to recognize out-of-distribution attack vectors (0.0% recall on PortScan/DDoS when trained only on DoS).
5. **High False Alarm Ratio on Bot Traffic:** 35 clean benign flows were misclassified as Botnet activity, compared to only 12 true Bot flows detected.

---

## 11. Recommended Improvements

1. **Temporal & Session-Based Data Partitioning:**
   - Replace random stratified shuffling with time-windowed or day-based splitting (e.g. train on Monday–Thursday, test on Friday). This eliminates session flow leakage and tests realistic temporal generalization.
2. **Port Number Discretization / Ablation:**
   - Discretize `Destination Port` into categorical ranges (Well-Known: 0–1023, Registered: 1024–49151, Dynamic/Ephemeral: 49152–65535) or evaluate port-agnostic models to force decision trees to learn flow kinematics (IAT, burstiness, packet length variance) rather than static port numbers.
3. **Cost-Sensitive Learning & Class Balancing:**
   - Introduce `class_weight="balanced_subsample"` to heavily penalize misclassifications on rare attack classes (XSS, SQL Injection, Botnet, Infiltration).
   - Apply SMOTE or Tomek-Link resampling to the training set for minority classes.
4. **Hybrid Detection Engine (Supervised + Unsupervised):**
   - Deploy an unsupervised anomaly detector (e.g., Isolation Forest or Deep Autoencoder) alongside the Random Forest. While Random Forest excels at known attack classification, the unsupervised model catches out-of-distribution zero-day spikes that the supervised trees misclassify as Benign.
5. **Divergence-Triggered SOC Alerting:**
   - In production, when `Binary_Pred == "ATTACK"` but `Multi_Pred == "BENIGN"`, automatically route the flow to a tier-2 triage queue labeled *"Potential Zero-Day Anomaly"*.
